# Profiles

A profile gives a recurring endpoint a name. Instead of

```
mpt cp report.pdf "sftp://deploy@srv.example.com/data/incoming/?key=~/.ssh/prod_ed25519&hostkey=SHA256:f29GJDwDP5hekqa22VhNdaNPBM+q6AzG3FvQaBCJnmg&timeout=120"
```

you write

```
mpt cp report.pdf mpt://prod/incoming/
```

`mpt://<name>/<path>` works anywhere a URL is expected: as a source, as a
target, in `ls`, in a [job list](../guide/job-lists.md), as the relay behind
[`--via`](../server/relay.md). For [`mpt serve`](../server/serve.md#what-a-client-can-reach)
profiles are more than a convenience: by default they are the only endpoints
a job submitted over HTTP may name.

## Defining one

```toml
[profiles.prod]
url         = "sftp://deploy@srv.example.com/data/"
key         = "~/.ssh/prod_ed25519"
hostkey     = "SHA256:f29GJDwDP5hekqa22VhNdaNPBM+q6AzG3FvQaBCJnmg"
timeout     = 120
hash        = "blake3"

[profiles.archive]
url        = "s3://archive-bucket/reports/"
endpoint   = "https://minio.example.com"
path_style = true
via        = "mpt://relay"           # written by the relay, not from here

[profiles.boss]
url     = "mailto:boss@example.com"
subject = "Report"
```

`url` is the only required key. Everything else falls into two groups:

- **Five reserved keys** set transfer options for that endpoint: `sign`,
  `hash`, `atomic`, `password` (which takes a [credential
  reference](credentials.md)) and `via`, the [relay](../server/relay.md) this
  endpoint is reached through.
- **Everything else becomes a URL option.** `key`, `hostkey`, `timeout`,
  `endpoint`, `path_style` and `subject` above are not a fixed list; they are
  appended to the profile's URL. A profile can therefore carry any option its
  scheme understands, and a typo shows up as an option the protocol ignores
  rather than as a configuration error. An option that holds a secret
  (`passphrase`, `token`, an `Authorization` `header`) takes a [credential
  reference](credentials.md#where-a-reference-may-be-used) like `password`
  does, and makes the file one that [must not be readable by
  others](file.md#permissions).

A key that takes several values may be written as a list:

```toml
[profiles.prod]
url     = "sftp://deploy@srv.example.com/data/"
hostkey = ["SHA256:f29GJDwDP5he…", "SHA256:2mGf4C1Pq0Xk…"]   # during a key rotation
```

## Seeing what is defined

```
$ mpt profiles
mpt://archive  s3://archive-bucket/reports/?endpoint=https://minio.example.com&path_style=true
    via    mpt://relay
mpt://boss  mailto:boss@example.com?subject=Report
mpt://prod  sftp://deploy@srv.example.com/data/?hostkey=SHA256:f29GJDwDP5hekqa22VhNdaNPBM+q6AzG3FvQaBCJnmg&key=~/.ssh/prod_ed25519&timeout=120
    hash   blake3
```

Each profile is shown as the URL it stands for, with the reserved keys on
their own line beneath. Passwords are masked. This is the quickest way to
check that a profile expands to what you meant, and it makes no connection.

## Path resolution

The path of the reference is appended to the profile's own path:

| Reference | Becomes |
|---|---|
| `mpt://prod` | `sftp://deploy@srv.example.com/data/` |
| `mpt://prod/` | the same |
| `mpt://prod/incoming/` | `…/data/incoming/` |
| `mpt://prod/incoming/x.pdf` | `…/data/incoming/x.pdf` |

The [trailing-slash rule](../getting-started/addressing.md#where-a-file-lands)
applies to the result, as always.

A reference is read like any other URL: its path is percent-decoded
(`mpt://prod/a%20b.pdf` names `a b.pdf`), a `#fragment` is not part of it,
and the prefix may be written in any case (`MPT://prod/`).

A reference cannot climb out of the profile's path, whether the `..` is
written out or percent-encoded as `%2e%2e`:

```
$ mpt ls "mpt://prod/../etc/"
error: configuration: mpt://prod/../etc/: invalid URL: unsafe file name '..': refers to a directory
```

That matters when the path comes from somewhere else, such as a job list
generated by another program or a CI variable. `mpt://prod/` is then a
boundary, not just an abbreviation.

## Overriding a profile

Options on the reference win over the profile's own:

```
mpt cp report.pdf "mpt://prod/incoming/?timeout=300"     # this one transfer may take longer
```

That is the general [precedence rule](file.md#precedence): the more specific
the place, the more it counts, which also puts a profile's endpoint options
above a command-line flag. The reserved keys are run-wide settings and go the
other way: `--hash sha256` beats `hash = "blake3"`. `via` is the exception
among them, because it is about this endpoint and not about the run: a
profile's `via` wins over `--via` and `[defaults] via`, and only `--no-via`
switches every relay off together.

## When to define one

Profiles pay off where an endpoint carries settings that are tedious and
error-prone to repeat: a pinned host key, a specific key file, a non-standard
S3 endpoint, a subject line. Some patterns that work well:

```toml
# The partner whose FTP server needs implicit TLS and a password from the key store
[profiles.partner]
url      = "ftps://upload@ftp.partner.example/in/"
tls      = "implicit"
passive  = true
password = { keyring = "mpt/partner-ftp" }

# The release bucket, where everything must be signed
[profiles.releases]
url  = "s3://releases/artifacts/"
sign = "ssh:~/.ssh/release_ed25519"
hash = "sha256"

# The archive host, patient because it is on the other side of a slow link
[profiles.archive]
url     = "sftp://archive@nas.example.com/vol1/backups/"
key     = "~/.ssh/archive_ed25519"
timeout = 600
```

With `sign` in the profile, a copy to `mpt://releases/` is signed whether or not
the command asks for it: the decision is recorded in one place.

## Limits

- **Profiles do not chain.** A profile's `url` may not be another `mpt://`
  reference. `via` is the one key that may name another profile — the relay
  the endpoint is reached through — and that profile's `url` has to be an
  `ssh://` URL of its own.
- **`./mpt.toml` may not define profiles.** A file in the working directory
  can tune how a transfer runs, never where it goes; see
  [the file in the working directory](file.md#the-file-in-the-working-directory).
- **An unknown name is an error**, and the message says what does exist:

  ```
  $ mpt ls mpt://nosuch/
  error: configuration: no profile 'nosuch' (known: boss, prod)
  ```
